# Методика измерений

На первом этапе требуется только базовый контрольный запуск. Полная матрица и выбор оптимизированной конфигурации выполняются позже. Числа из модульных тестов с FakeEncoder не являются измерениями производительности модели.

## Объект и база сравнения

База: `intfloat/multilingual-e5-small`, закреплённая ревизия из `model-lock.json`, CUDA, FP32, пакет 32. Веса находятся на GPU, `eval`/`inference_mode`, TF32 отключён, attention implementation = eager во всех сравниваемых конфигурациях. FP16 переводит веса и вычисления модели в half; конечные нормализованные векторы и скалярное произведение хранятся в FP32. Обучения и генерации нет.

Переход MiniLM→E5 нужно оценивать отдельным исследованием качества и времени при равных условиях. Замена интерфейса и чтение готового индекса не объявляются GPU-ускорением.

## Границы и память

Перед каждым режимом выполняется минимум один прогрев на полном корпусе, затем минимум три измеряемых повтора. Каждый повтор заново читает документы из SQLite, формирует фрагменты, кодирует их и сохраняет отдельный временный NPZ с `flush`/`fsync`. Рабочий индекс приложения не изменяется. Файловый кэш Windows между повторами не очищается; это повторные замеры при прогретом кэше, а не холодное чтение диска.

- `prepare_seconds`: чтение уже извлечённого текста из SQLite и фрагментация. Первичное чтение/парсинг PDF/DOCX/TXT при импорте **не включено**. Отдельное профилирование первичного импорта остаётся следующим этапом.
- `encode_seconds`: проверка токенов, токенизация, подготовка пакетов, передача на GPU, вычисления, нормализация и возврат векторов на CPU. Это полное время `encode`, а не чистое время CUDA-ядер. Дополнительная предварительная проверка длины токенов включена.
- `save_seconds`: проверка неизменности набора, контрольные суммы, сериализация и запись NPZ на диск.
- `total_seconds`: сумма этих трёх интервалов. Загрузка модели, проверка файлов модели, прогрев, качество, удаление временного файла и CSV сюда не входят.
- `chunks_per_second`: число фрагментов / `encode_seconds`.
- `peak_allocated_mib`, `peak_reserved_mib`: пиковые значения PyTorch, включая веса модели, после сброса счётчиков перед повтором. Не вся видеопамять, занятая Windows и другими программами. Reserved после прогрева может сохранять кэш аллокатора; кэш между повторами не очищается. На CPU поля пусты, а не нулевые «GPU-замеры».
- `query_median_seconds`: медиана отдельных запросов при проверке качества; модель и индекс уже открыты, запрос прогрет. Включены encode запроса и поиск top-5 на CPU.

Перед началом интервала и после нейросетевой обработки вызывается `torch.cuda.synchronize()`. OOM и другие ошибки не запускают молчаливую замену устройства, точности или пакета; они записываются с номером повтора и фазой. Ошибка прогрева сохраняется как repeat=0. Незавершённые повторы не участвуют в медиане. Ускорение не вычисляется при менее чем трёх успешных повторах.

## Данные и качество

`examples/quality_questions.json` — 32 заранее размеченных вопроса к старым демоинструкциям. Правильные ответы заданы как точные ID фрагментов. Наличие всех ID проверяется до измерений; сохраняются исходная разметка, её SHA-256, найденные ID, оценки, Hit@5 и время каждого вопроса каждого повтора. Hit@5 — доля вопросов с хотя бы одним правильным фрагментом среди первых пяти.

Это ограниченная учебная выборка по знакомой демонстрационной базе. Для окончательной работы нужны проверка разметки человеком и дополнительная выборка по разрешённым документам. При изменении разбиения вопросы и ID сверяются заново до сравнения режимов. Кандидат допускается к выбору только при отсутствии снижения Hit@5; сами изменения выдачи анализируются по `quality.csv`. Отсутствие разметки не считается нулевым или идеальным качеством.

## Следующий этап

Запускайте из `app`, закрыв другие процессы индексации и по возможности снизив фоновую нагрузку GPU. Не запускайте сравниваемые конфигурации одновременно. Для окончательного исследования рекомендуется чередовать порядок конфигураций и повторить базовый режим в конце; автоматический планировщик порядка пока не реализован.

```powershell
# Качество и скорость на исходной коллекции
..\.venv\Scripts\python.exe -X utf8 cli.py --device cuda --precision fp32 benchmark --batches 8 16 32 64 128 --repeats 3 --warmups 1 --labels examples/quality_questions.json
..\.venv\Scripts\python.exe -X utf8 cli.py --device cuda --precision fp16 benchmark --batches 8 16 32 64 128 --repeats 3 --warmups 1 --labels examples/quality_questions.json

# Искусственная нагрузка (отдельно от качества)
..\.venv\Scripts\python.exe -X utf8 cli.py --device cuda --precision fp32 benchmark --batches 8 16 32 64 128 --target-fragments 1000
```

Повторите искусственные нагрузки для 100/1000/5000 фрагментов и FP16. `--target-fragments` доводит исходную коллекцию до указанного размера повторением текстов с новыми ID; это обозначено `synthetic=true`. Такой режим не допускает разметку качества: одинаковые фрагменты искажают top-5. Желательно дополнительно измерить реальные документы различной длины; повторение коротких текстов не заменяет их.

Каждый запуск сохраняет `manifest.json`, `chunks.json`, `runs.csv`, при разметке — `labels.json`, `quality.csv`. Числа и ошибки сохраняются после каждого повтора. Таблица интерфейса показывает медианы, min/max времени и число успешных повторов, графики — время, скорость, память и качество. Экспорт CSV использует UTF-8 с BOM для Excel.

Сравнение разрешено только при совпадении `comparison_key`: документы и фрагменты, модель, ревизия, параметры, среда, протокол и разметка. Ускорение — медиана полного времени CUDA FP32/32 / медиана полного времени кандидата. Ссылка на использованный базовый запуск сохраняется в сводной таблице. При повторной базе выбирается самая поздняя сопоставимая. Для окончательной работы сохраняйте CSV сводки вместе с сырыми повторами.

Остаются профилирование CPU/GPU (отдельные прогоны PyTorch Profiler, не смешанные с временными замерами), анализ передачи и padding, поиск фактического узкого места и проверка улучшения. Ускорение, экономия энергии, отзывы сотрудников и внедрение заранее не заявляются.
